# Grok Imagine

Read this when generating with xAI's Grok Imagine video models. Checked against xAI's documentation
on 2026-10-27; models and parameters change, so confirm names and limits in the current reference
before a run, and trust it over this page when they disagree.

## Which model for which job

| Job | Model | Why |
|---|---|---|
| A clip from a start frame | `grok-imagine-video-1.5` | `image` is the starting frame; up to 1080p native |
| A clip with a pinned end frame, a loop, or mid keyframes | `grok-imagine-video-1.5` | the only model with `last_frame` and `keyframes` |
| A clip guided by reference images of the person | `grok-imagine-video-1.5` | up to 14 references, up to 720p |
| Fixing one detail of an otherwise good clip | `grok-imagine-video` | video editing, source up to 8.7 s |
| Extending a clip | `grok-imagine-video` | extension adds 2–10 s from the last frame |

The `-lite` model has no frame pinning or references, so it cannot keep a chain or a loop.

## Map the workflow onto its controls

- **Start frame** → `image`. Image-to-video output always takes the input image's aspect ratio and
  ignores `aspect_ratio`, so make every keyframe at the delivery aspect ratio.
- **End frame** → `last_frame`, which pins the exact last frame. **A loop** is the same image as
  `image` and `last_frame`.
- **Mid keyframes** → `keyframes`, up to four, each an image and a `timestamp_s` greater than 0 and
  less than `duration`, snapped to a third-of-a-second grid. The melt rule applies between every
  pair of pinned frames: pin only frames a few seconds of plausible motion apart.
- **References** → reference images, each referred to in the prompt by position as `<IMAGE_0>`,
  `<IMAGE_1>`; when `image` is pinned it takes `<IMAGE_0>` and references start at `<IMAGE_1>`.
  References do not lock the first frame. Give each one role, keep the cast small.
- **Duration** → `duration`, 1 to 15 s, default 8. Ask for the shortest that holds the one action,
  usually 3 to 6 s; the default is longer than most single actions.
- **Resolution** → `resolution`, default 480p. Set it explicitly every time. Clips using frame
  pinning or references top out at 720p while plain image-to-video goes to 1080p, so generate a
  whole chain or reel at one resolution, 720p when any shot needs pinning; mixed resolutions do not
  join cleanly.
- **Audio** → generated by default, with lip-synced speech on the 1.5 models. Request a silent
  video (`generate_audio` off) unless the footage needs sound, and still check the mouth: a person
  who moves their lips with no speech reads as broken. Normalizing strips any audio track anyway.
- **Prompt** → optional when a frame is pinned. Write it anyway: the one motion, its pace and size,
  then the hold line. The video API documents no negative-prompt field, so the hold line lives in
  the prompt.

## Inside an agent with a built-in video tool

Grok Build gives its agent one video tool, `reference_to_video`, with the same model behind it but
its own parameter names (checked against Grok Build 1.0.70's bundled guidance):

| Workflow | Tool parameter |
|---|---|
| Start frame | `first_frame`: pinned as the exact first frame |
| End frame, loop | `last_frame`; the same image in both makes a loop |
| Mid keyframes | `keyframes`: up to four `{image, timestamp_s}`, on the third-of-a-second grid |
| References of the person | `images`: up to 14, re-rendered rather than shown literally |
| Prompt | `prompt`, required |
| Aspect ratio | `aspect_ratio`, required: set it to the keyframes' ratio |
| Duration | `duration`, 1 to 15 s, default 6 |
| Resolution | `resolution_name`, 480p or 720p: set 720p for the whole sequence |

Prompt tags count in upload order `first_frame`, `images`, `keyframes`, `last_frame`: with a
`first_frame` set, the first reference is `<IMAGE_1>`. On some account tiers the tool returns an
upgrade notice instead of a video; relay it and stop rather than retrying.

That bundled guidance extracts the next clip's start frame with a time seek near the end of the
file. Use the exact last decoded frame instead (frame count, then frame N−1, in
[frames and assembly](frames-and-assembly.md)); the time seek can land a frame early and the join
jumps.

## Workflow notes

- Requests are asynchronous: submit, poll the returned request ID, download. Returned URLs are
  temporary: download every take into staging immediately, named by shot and take, and log it.
- **Prefer chaining over extension** for continuous footage. Extension returns the original and the
  extension as one file, caps at 720p, and is generated by the older model. Chaining a new 1.5 clip
  from the exactly extracted last frame keeps each clip judged on its own and the model consistent.
  When extension is used, split the result at the original's frame count and judge the new part as
  a new clip.
- **Video editing** keeps the rest of the clip "as close to the source as it can", which is not
  identical: after an edit, judge the whole clip again, and re-check its first and last frames
  against the neighbouring clips, because a re-rendered join frame breaks the chain.

## A request for a chain link

```json
{
  "model": "grok-imagine-video-1.5",
  "prompt": "She takes three unhurried steps toward the counter, the parcel swinging slightly in her right hand. Nothing else in the scene changes: no objects or people appear or disappear, her clothes and the parcel stay the same, and the lighting does not change. The camera stays still.",
  "image": {"url": "<exact last frame of entry-01>"},
  "duration": 5,
  "resolution": "720p"
}
```

A loop on the rest frame (set audio off with the option name the current reference gives):

```json
{
  "model": "grok-imagine-video-1.5",
  "prompt": "She breathes slowly and blinks, glances down at the desk and back up at the camera. Nothing else in the scene changes: no objects or people appear or disappear, and the lighting does not change. The camera stays still.",
  "image": {"url": "<rest frame R>"},
  "last_frame": {"url": "<rest frame R>"},
  "duration": 6,
  "resolution": "720p"
}
```
